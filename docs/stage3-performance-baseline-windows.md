# Windows Release 性能与功能基线（阶段 3 前）

## 目的与边界

本报告记录阶段 3（格式兼容和恢复效率）开始前的 Windows Release 功能与性能基线，供后续重构（尤其无锁优化）作同机对照。数据库工作目录显式位于 C: Samsung NVMe；不是 D: 机械硬盘。本文结果只代表本机 Windows 环境，不替代 Linux/WSL 验证。

## 硬件与构建环境

| 项目 | 配置 |
|---|---|
| OS | Windows 11 Pro for Workstations，版本 10.0.26300，64 位 |
| CPU | Intel Core i7-8700，6 核 / 12 逻辑处理器；采样时约 3.192 GHz |
| 内存 | 31.81 GiB |
| NVMe（测试盘） | C:，SAMSUNG MZVLQ256HAJD-00000；标称约 237.5 GiB，采集时可用 108.8 GiB |
| 其他盘 | D: 为 ST2000VX003-1HH164 HDD，不用于本次数据库文件 |
| 电源计划 | 平衡 |
| 编译 | Visual Studio 2026 / MSVC x64，CMake + Ninja，Release `/O2 /Ob2 /DNDEBUG` |

硬件信息由 Windows CIM/PowerShell 查询；C: 容量与 Samsung 盘容量相符。开始硬件探测时 CPU 负载约 19%，不是隔离的性能实验机；运行中未固定 CPU 频率或关闭其他进程。当前工作区不是 Git 仓库，因此本报告无法绑定提交哈希；后续对比时应同时归档候选源码版本。

## 数据路径与复现命令

所有基准数据库都由命令行显式指定在 NVMe：

- 功能测试：`C:\lsm_stage3_baseline\functional`（设置 `LSM_TEST_DB_ROOT`）
- 单线程基准：`C:\lsm_stage3_baseline\benchmark_single`
- 多线程基准：`C:\lsm_stage3_baseline\benchmark_mt`
- 完整 stdout/stderr 日志：`C:\lsm_stage3_baseline\logs`

```powershell
$env:LSM_TEST_DB_ROOT = 'C:\lsm_stage3_baseline\functional'
.\out\build\x64-release\lsm_test.exe
.\out\build\x64-release\lsm_bench.exe 500000 500000 0 C:\lsm_stage3_baseline\benchmark_single
.\out\build\x64-release\lsm_bench_mt.exe 8 500000 200000 0 C:\lsm_stage3_baseline\benchmark_mt
```

两个 benchmark 均使用 `sync_wal=0`。每次运行创建唯一子目录并在正常退出时清理数据库；输出会打印实际 DB root。该设置度量的是当前默认非同步 WAL 工作负载，不代表每次写入均已落盘的同步耐久性吞吐。

## 单线程端到端基准

每轮含 500,000 次顺序 Put、500,000 次随机命中 Get、500,000 次未命中 Get，以及 500,000 次混合操作（249,975 Put / 250,025 Get）；重启后校验 500,000 个基础键和 249,975 个混合键。五轮均无错误，重启数据校验成功。

|---:|---:|---:|---:|---:|---:|
| 1 | 142,564 | 504,444 | 5,253,541 | 241,242 | 0.819 s |
| 2 | 138,387 | 514,270 | 5,238,740 | 241,227 | 0.813 s |
| 3 | 139,844 | 509,093 | 5,172,230 | 237,555 | 0.812 s |
| 4 | 143,953 | 515,145 | 5,166,554 | 241,742 | 0.790 s |

### 延迟采样摘要

延迟是每 64 次操作采一个单操作耗时样本，统计的是样本的分位数，不是全部操作的分位数。以下为五轮结果的中位数：

| 阶段 | p50 | p95 | p99 |
|---|---:|---:|---:|
| 顺序写 | 5 us | 6 us | 10 us |
| 命中读 | 1 us | 2 us | 15 us |
| 未命中读 | 0 us | 0 us | 0 us |
| 混合操作 | 4 us | 5 us | 15 us |

微秒计时及整型截断导致未命中读分位数显示为 0 us；它不代表零延迟，不应用于延迟回归判定。单次最大值受调度/后台工作影响显著，也不作为稳定门槛。

## 8 线程并发基准

每轮先顺序写入 500,000 个基础键，再以 8 线程各写 200,000 个互不相同的键（并发写 1,600,000 次；总计 2,100,000 个键），随后以 8 线程各读 200,000 次。每轮并发写错误、基础键校验错误、读 miss/wrong、并发后校验错误均为 0；重启后均验证了全部 2,100,000 个键。

## 后续优化对照门槛

无锁或其他性能改动的候选版本应使用相同机器、Release 配置、WAL 同步开关（本基线为 `sync_wal=0`）、工作负载、NVMe 路径和五轮采样。至少对照以下五轮**中位数**：

- 单线程：顺序写 142,564；命中读 514,270；未命中读 5,238,740；混合 241,242 ops/s。
- 并发：8 线程写 60,537；8 线程读 3,567,084 ops/s。
- 采样延迟：单线程写 p95/p99 6/10 us，命中读 2/15 us，混合 5/15 us；并发写 152/191 us，并发读 3/4 us。
- 功能正确性必须保持：全部 35 个回归用例通过；基准无错误、无数据错漏，且并发重启验证完整通过。

若候选版本五轮中位吞吐低于对应基线，或所列 p95/p99 中位数更差，应视为未达到“不劣于基线”；先在相同条件下复跑排除负载噪声，再决定是否接受。未命中读的 0 us 延迟不作门槛。测试期间应记录电源计划、磁盘剩余空间和显著系统负载，以便公平解释差异。
